## 2. Las palancas de mayor ROI (gratis, recurrentes)

> Ordenadas por impacto a las metas. Las top-2 mueven el GATE; las 3-4 mueven el UMBRAL.

1. **🥇 Funnel Shorts→Sleep (GATE).** Los Shorts top (`jvEokzazN4o` 4,975 views, `hvV1P06nUck`, `zfQYgA88gcU`) → pinned comment + end-screen al sleep 2h. Transferir 1-5% de tráfico = decenas-cientos de horas que hoy se pierden. **Pinned comments ya hechos (Y1, 06-10); falta end-screens (Fernando manual) + automatizar el pin en cada Short nuevo.** Es la palanca dormida #1.

2. **🥈 1 Short → 3 redes automático (GATE + UMBRAL).** Cada Short nuevo YT → auto-Reel FB + auto-Reel IG, los 3 con CTA al sleep. Una unidad de trabajo alimenta subs YT, fans FB y alcance IG simultáneamente. Hoy es manual/parcial → automatizable (§4).

3. **🥉 Cada historia long-form pare 1 Short (GATE).** La historia (motor de adquisición de horas) recorta su escena-hook como Short, que la alimenta de vuelta vía pinned. Loop cerrado: long-form trae horas → Short trae subs → subs ven más long-form. Producción nueva justificada = solo historias tipo Rut.

4. **Reel diario hook-first → fans FB (UMBRAL).** Ya activo (`auto-publicador-vdd` 16:30 MX). Es el driver del +42%/semana hacia los 5k. Mantener cadencia; **agregar variante: 1 de cada 3 imágenes con CTA a video** para no perder el tráfico-imagen.

5. **Binge playlists + end-screens encadenados (GATE).** Encadenar sleep→sleep y historia→historia con end-screens + playlists temáticas. Sube watch-hours/sesión sin producir nada nuevo (palanca de retención, gratis).

## 4. Brief para anti-venom (ejecución n8n/VPS)

> **Para anti-venom:** construir/extender estos workflows en n8n (VPS `root@2.24.111.80`). Usar `n8n-deploy` (gotchas conocidos: no heredoc con `*`, POST /activate tras PUT, correr desde VPS). Tokens FB/IG en `cero-agent/scripts/configs/tokens.json` key `palabra-de-dios`. Cada uno: trigger → acción → red destino → log a `/var/www/stats/actions.jsonl`.
> **Regla de oro:** todo CTA generado debe apuntar al **sleep/historia (GATE)** primero y Ko-fi segundo. NO publicar si hay strike activo (guardrail anti-slop).

### WF-1 — `vdd-short-to-3` (palanca #2) — **PRIORIDAD ALTA**
- **Trigger:** nuevo Short publicado en YT (poll YT Data API `search?forMine&type=video` filtrando `<60s`, o leer de `data/shorts_schedule.json` cuando `youtube_id` se llena post-upload).
- **Acción:** descargar/usar el MP4 → publicar como **Reel FB** (Graph API `/video_reels`) + **Reel IG** (`/media` type=REELS → `/media_publish`).
- **Red destino:** FB Page `452922677899760` + IG `17841469453382962`.
- **Copy:** hook del Short + CTA "mira el video completo para dormir 👉 [link sleep YT]" + Ko-fi en 2ª línea.
- **Dedup:** marcar en estado (`vdd_reposted.json`) por `youtube_id` — idempotente (patrón ig_state.json).
- **Log + Telegram:** `actions.jsonl` + ping `@cero_ops_bot`.
- **Success criteria:** Short nuevo aparece como Reel en FB+IG dentro de 6h, 0 duplicados, CTA al sleep presente.

### WF-2 — `vdd-short-autopin` (palanca #1, automatiza el funnel) — **PRIORIDAD ALTA**
- **Trigger:** mismo que WF-1 (Short nuevo YT).
- **Acción:** dejar + fijar (pin) comentario en el Short → CTA al sleep 2h destino + Ko-fi.
- **Red destino:** YouTube (comments API).
- **⚠️ Bloqueo conocido:** `yt-comments-agent` token muerto 27d (force-ssl). **Anti-venom debe re-mintear el refresh_token YT con scope `youtube.force-ssl`** o usar el token OAuth del comments-agent en n8n. Sin esto, el pin no se puede automatizar (hoy es manual vía Chrome MCP, bloqueado por classifier).
- **Success criteria:** cada Short nuevo tiene comment fijo → sleep dentro de 1h del publish.

### WF-3 — `vdd-longform-push` (extiende `lofi_push_plan` a historias) — **PRIORIDAD MEDIA**
- **Trigger:** nueva historia/sleep long-form con `youtube_id` real en `data/lofi_push_plan.json` (o nuevo `longform_push_plan.json`).
- **Acción:** FB post (thumbnail + link YT) + IG teaser/post ("link en bio") + pinned comment en el video YT (→ siguiente historia/playlist binge).
- **Red destino:** FB + IG + YT.
- **Copy:** brief por video del plan JSON (venom lo llena post-upload, patrón handoff estándar del CLAUDE.md).
- **Success criteria:** cada long-form publicado genera 1 FB post + 1 IG + 1 pinned comment con CTA binge en 6h.

### WF-4 — `vdd-fb-reel-to-ig` (C5, vanity) — **PRIORIDAD BAJA**
- **Trigger:** nuevo Reel FB del `auto-publicador-vdd`.
- **Acción:** repostear el mismo Reel a IG si no salió ya por WF-1.
- **Red destino:** IG.
- **Nota:** baja prioridad (IG es vanity por North Star). Construir solo si WF-1/2/3 ya corren.

### Lo que anti-venom NO debe tocar (ya vive y funciona)
`auto-publicador-vdd` (Reel diario imagen) · `metricas-vd-engagement` · `daily-stats-vdd` · responders de comentarios · imágenes FB/IG 9am·1pm·7pm (launchd Mac, Track 3). **No duplicar el Reel-imagen diario** — WF-1 es para el **Short-video**, distinto.
